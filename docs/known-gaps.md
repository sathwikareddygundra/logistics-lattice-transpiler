# Known gaps across plants (T-9)

Generated by `scripts/build_inventory.py`.

1. Dispatch_Date is stored in both dispatch and turnaround_time in the source CSVs; the canonical model owns it once (on dispatch).
2. tracking.last_known_location mixes hub codes (Hub_323) and city names in one column.
3. turnaround_time.total_tat_hours takes only about 22 distinct values: bucketed, not raw.
4. There are no dimension tables for drivers, warehouses or carriers.
5. Plants use different physical table names (dispatch vs ycw_dispatch vs vgu_dispatch); ir/adapters.py normalizes this once, at IR level.
6. Plants run different engines (SQLite, DuckDB, PostgreSQL-capable); timestamps are TEXT in SQLite but TIMESTAMP in DuckDB and PostgreSQL. Dialect handling: docs/dialects.md.
7. Each plant holds a disjoint third of the invoices (invoice sequence number mod 3), so plant-level totals only make sense summed across plants.
